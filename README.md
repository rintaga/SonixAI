# Sonix AI 3.0

Sonix AI is an independent AI application and model-development project. Its goal is to build a Sonix-branded assistant through a reproducible dataset, training, evaluation, model-artifact, and inference pipeline.

> **Current model status:** Sonix uses a LoRA adapter fine-tuned from a compatible pretrained base model. It is not yet a foundation model trained from random initialization. The adapter must be used together with its compatible base model.

## Project Components

- **Android Client:** Java-based Android application.
- **Training Dataset:** Instruction/input/output examples in JSONL format.
- **Training Pipeline:** Python, PyTorch, Transformers, and PEFT.
- **GitHub Actions:** Automated CPU training and Android APK builds.
- **Inference Server:** FastAPI service with a Chat Completions-compatible endpoint.
- **Model Artifacts:** Downloadable adapter files generated by GitHub Actions.

## Training Sonix AI 3.0

1. Open the repository's Actions tab.
2. Select **Train Sonix AI 3.0**.
3. Choose a compatible pretrained base model.
4. Select the maximum training steps.
5. Start the workflow.
6. Download the `Sonix-AI-3.0-Adapter` artifact when training completes.

The default base model is `Qwen/Qwen2.5-Coder-0.5B-Instruct`.

GitHub-hosted CPU runners provide isolated resources. Multiple free Actions jobs do not combine their CPU or RAM into one large computer. Parallel jobs can perform separate experiments or data-processing tasks.

CPU-based fine-tuning is suitable for small experiments. It is not a practical way to train a capable large language model from scratch.

A LoRA adapter contains learned parameter updates, not the complete base model. Keep the exact base model ID and adapter version together.

## Dataset Format

Each non-empty line in `training/dataset.jsonl` must contain a JSON object:

```json
{
  "instruction": "User request or task",
  "input": "Optional context",
  "output": "Expected assistant response"
}
```

Use accurate, diverse, and permission-safe examples. Never include passwords, API keys, private information, or datasets without appropriate rights.

## Inference Server

The inference server loads a compatible base model and the matching Sonix adapter.

See [server/README.md](server/README.md) for deployment instructions.

The Android APK does not bundle model weights. GitHub Actions creates downloadable artifacts; it does not provide permanent model hosting.

Deploy the inference service on a trusted host with sufficient memory. Configure HTTPS and protect the API with a strong key. Never commit credentials to this repository.

## Android Application

- Application ID: `com.sonix.ai`
- Minimum Android SDK: 23
- Target Android SDK: 32
- Java: 17
- Android NDK: `27.2.12479018`
- Native C++ standard: C++17
- Supported ABIs: `armeabi-v7a`, `arm64-v8a`

Use the **Build Sonix AI APK** workflow to generate the Android debug APK.

## Development Principles

- Keep training data and model configurations versioned.
- Track the base model and adapter versions.
- Report training and evaluation results honestly.
- Never describe a LoRA adapter as a model trained from scratch.
- Keep API keys and credentials out of source control.
- Maintain compatibility between the Android client and inference server.

## Roadmap

1. Expand and improve the training dataset.
2. Add repeatable dataset validation and model evaluation.
3. Track model and adapter versions.
4. Improve inference deployment and monitoring.
5. Explore larger-scale training when suitable compute resources are available.
